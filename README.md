# 明尼助手

面向明大中国学生的校园服务小程序。微信小程序 + 微信云开发（CloudBase），无自建服务器、无独立后台网站——管理职能按角色内嵌在小程序里。

## 模块

首页（`pages/home`）按开关渲染入口：

| 模块 | 入口页 | 说明 |
|---|---|---|
| 二手市场 | `pages/market` | 发布、浏览、举报 |
| 公寓转租 | `pages/subletmarket` | 找房、转租、找室友 |
| 任务委托 | `pages/taskmarket` | 代买、代取等 |
| 兴趣群组 | `pages/groupmarket` | 找搭子（一次性，过了活动日期自动下架）、长期群招新 |
| 一起拼团 | `pages/shoplist` | 店长开团、满单成团、送到学校取货点（2026-10-11 前叫校外服务） |
| 意见反馈 | `pages/feedback` | |

一起拼团有两种形态，由 `SHOP_MODE` 切换（见下）：**黄页**只展示店铺和商品信息，买家复制店长微信自己联系；**订单**是完整的拼团下单流程（见下面「一起拼团」一节）。

兴趣群组只做「发现层」：小程序里是群卡片 + 公开留言，想加入的人复制群主微信号、由群主拉进微信群。不做小程序内群聊（会把平台变成通信服务提供者，跨太平洋延迟也撑不起实时聊天），也不收微信群二维码（7 天过期、满 200 人扫不进）。

配送队（`TEAM_MODULE_ENABLED`）2026-10-11 起关着：还没有配送队，一律店长自己送。

## 一起拼团

店长在「我的小店」的日历里挑一天开团，买家下单参团，截单时够门槛就成团。

**场次**（集合 `shop_sessions`，一家店最多同时开 4 场）：
- 店长选出发日期和时间、截单几点（**固定在出发前一天**）、成团门槛（按单数，可以不设）、每周重复、这一场去哪几个取货点（店铺取货点的快照）。
- 确认截止不让店长填：截单后 12 小时，最晚出发前 1 小时。
- 有人下单后日期、时间、取货点都定死了，只能调低门槛、开关每周重复。截单前店长可以点「照常送」（不够门槛也成团），出发前可以取消这一场（进行中的单一起取消）。
- 日历上能看到别家两周内的排期（灰点），方便错开；只显示买家本来就看得到的东西，不显示单数。

**订单状态**：`forming` 拼团中 → 截单 → `confirming` 待确认 → 店长「确认订单」→ `accepted` 已确认 → `delivering` → `completed`。没成团、确认截止前没确认、买家或店长取消都是 `cancelled`。改版前的老单 `pending` 照旧走「接单」。

**平台不经手钱，也不出现任何付款指引**（《店长责任告知书》第六节）：「待确认」只是请买家在截止前联系店长，「确认订单」只表示店长认了这一单，之前收不收钱是他们俩在小程序外的事。

**爽约**：成团后买家自己取消、或者确认截止前没被确认，记一次（`shop_orders.no_show`）；30 天里满 2 次暂时不能参团。拼团中取消不算。

**定时结算**：云函数 `groupSettle` 每 5 分钟跑一次（`config.json` 里的 timer 触发器），每一步都是带旧状态的条件更新，重复跑、跑到一半超时都没关系：
0. 截单前 2 小时还没到门槛的场次，给已下单的买家各发一条「拼团进度通知」（还差 N 位），每场只发一次。这张票是下单时和订单进度一起单独要的，有门槛的团才要
1. 到了截单时间的场次判成团 / 未成团
2. 这些场次里的单推进到待确认 / 取消，给买家发订单进度通知（用下单时那张授权票）
3. 确认截止已过还没确认的单取消，记爽约
4. 出发后收尾；开了每周重复的开下周同一时间的新场次，并发开团提醒

**开店码**：开店要填管理员在「我的 → 开店码」生成的 8 位码（集合 `shop_create_codes`），一码一店、7 天过期。之前开好的店不受影响。

**没有营业中 / 打烊**：某天能不能下单只看那天有没有场次。`shops.status` 只剩被举报下架时写的 `closed`（和 `takedown` 一起），别处不再读；`shops.batches`、`business_hours` 老数据留着不读。老的纯线上服务店（`needs_delivery: false`）保留原样，开不了团。

**转发**：参团成功页、我的订单、列表顶上「我的拼团」都能直接转发，标题按进度写（「我拼了 XX，再来 3 位就开团」）。转发链接带 `from=share`，从卡片点进来下的单记 `shop_orders.source = 'share'`。没有任何转发奖励（微信禁止诱导分享）。

**转发卡片、长图海报、店铺页配色**：每家店长得不一样，不用小程序自己的栗色和金色。
- 配色从店铺 logo 取色（`components/groupShare` 的 `themeFor`、`utils/theme.js` 的 `fromColors`，字和底色对比度不够就换成黑或白）；风格三选一，版式本身不同：杂志（magazine）、黑板（chalkboard）、手账（scrapbook），店长在「我的小店 → 场次 → 海报」里切（`shops.poster_style`，`shopManage` 的 `setPosterStyle`），转发卡片和店铺页跟着用。
- 长图海报（`utils/groupCover.js` 的 `renderLong`）把在售的东西全部列出来：有照片的两列卡片，没照片的「名字 ······ 价格」一行字，开了分类就分组；最多 80 样，超过 36 张照片后面的改成一行字（手机画布太高画不出来）。底部是取货点、门槛、截单时间和小程序码。转发卡片（5:4）现画：卖得最多的那道菜 + 广告语 + 当时的进度。
- 店铺点单页的场次、进度条、按钮、价格用这家店的强调色（`cssVars`，在白底上读不清的会压暗再用）。
- 二手「海报分享」也是长图，列出全部在售闲置（`getUserStore` 传 `poster: true`），配色从头像和商品照片取色，手账风。
- 转发卡片上的那道菜是**卖得最多的**（`shopBrowse` 的 `items[].sold`）。闲置主页的转发用**最可能卖掉的那件**：有照片的里面，留言问过的不同的人最多的（卖家自己回复不算），一样多挑新的（`getUserStore` 的 `hot_item`）；标题「【出】宜家书桌 九成新 $30 · 还有 6 件」，封面是它的图。
- 海报出图后用 `wx.previewImage`（`showmenu`），长按保存、发给朋友。
- 店名改了，还没结束的场次上的店名跟着改；拼团列表、我的订单都显示店铺现在的名字（订单上存的店名只在店删了时兜底）。
- 海报上的小程序码 scene 是场次 ID（`getMiniCode` 传 `sessionId`），扫进来的单记 `source = 'poster'`；小程序码只认已发布版本，体验版里扫不出来，会画「搜明尼助手」。
- 广告语由店长在小店设置里自己填（`shops.slogan`，16 字内），用作海报大标题和店长自己转发的卡片标题；买家转发用第一人称进度标题。
- 展示字体是站酷庆科黄油体（SIL OFL，可商用），只留 GB2312 一级常用字转成 WOFF，约 800KB。主包放不下，放在云函数 `appAssets` 里，第一次有人要时传进云存储（记在集合 `app_assets`），小程序端 `utils/fonts.js` 用 `wx.loadFontFace` 全局加载；加载不上退回系统黑体。
- 2026-10-12 试过用腾讯混元写广告语、出设计稿和背景图（云函数 shopAI），额度没批下来、一直 429，删了。代码没提交过，git 历史里没有。

**网页店长后台**（2026-10-16，网站在 minne-web 的 `/shop`）：店长在「我的小店 → 电脑上管理」（`pages/shopweb`）拿 8 位登录码，网页上输入后 7 天内不用再登。网页经 HTTP 访问服务调 `shopManage`、`shopOrders`，身份是登录凭证换出来的店长，只开放订单、场次、商品（导入菜单、文字、价格、照片、上下架）（白名单 `WEB_ACTIONS`）；开店、店铺资料、海报、删店还是只在小程序里。网页上改商品文字由 `shopManage` 调腾讯云 TMS 审核，因为微信的 msgSecCheck 要求发布者两小时内打开过小程序；商品照片先试微信 imgSecCheck，调不通再用腾讯云 IMS（见 `imageCheck`）。部署步骤见 minne-web 的 README「店长后台」。

**上线前**：部署 `groupSettle`（连同触发器一起上传，超时在控制台调到 60 秒）、`shopManage`、`shopBrowse`、`buyerOrders`、`shopOrders`、`shopSubscribe`、`sendSubscribe`、`handleReport`、`getMiniCode`、`getUserStore`、`appAssets`（字体）。`shop_sessions`、`shop_create_codes` 两个集合第一次用时自动建，建好后在控制台把权限改成「所有用户不可读写」。

## 功能开关

见 `miniprogram/config.js`：

- `SHOP_MODULE_ENABLED = true` — 一起拼团整体开关。关掉后首页和「我的」页的相关入口全部消失（含配送队），其余模块不受影响。
- `SHOP_MODE = 'catalog'` — 一起拼团的形态：
  - `'catalog'` 黄页 —— 只展示信息，买家复制店长微信自己联系。没有购物车、订单、配送、起送价。
  - `'order'` 订单 —— 完整下单流程。
  
  **这个值直接决定能报什么服务类目。** 微信「电商平台」类目的定义是「为多个经营者提供交易场所」，`'order'` 正落在里面；而该类目通过后**强制要求绑定微信支付商户号并接入订单发货管理**。有没有支付不是分界线——货到付款的电商也是电商，分界线在有没有下单闭环。所以在真的接入微信支付之前，只能用 `'catalog'` 提审。
  
  ⚠️ 云函数 `buyerOrders` 里有一份同名常量，那边才是真闸门（前端拦得住手滑，拦不住改包）。**两边必须同时改，并重新部署。**
- `TEAM_MODULE_ENABLED = false` — 配送队（建队、发配送请求、我的配送、配送管理）。2026-10-11 关掉，还没有配送队。
- `GROUP_MODULE_ENABLED = true` — 兴趣群组。关掉后首页、发布页、「我的」页的入口消失。
- `DEBUG_TIMING = false` — 请求延迟测量，开着时打印 `[timing]` 日志并在市场页显示测试按钮。**提审前必须关掉。**

老的外卖拼团模块（`FOOD_MODULE_ENABLED`、`pages/index`、`pages/myorders`）已于 2026-09-19 删除，功能由校外服务完整覆盖，需要时从 git 历史取回。配套的一次性迁移入口（商家菜单页「从旧外卖菜单导入」+ `shopManage` 的 `importLegacyMenu`）已于同日移除，`menu_items` 集合在代码里已无任何引用，可在云开发控制台删除。

## 本地运行

1. 用[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)导入本目录（AppID 见 `project.config.json`）。
2. 在 `miniprogram/app.js` 里把 `env` 换成你自己的云开发环境 ID。
3. 在开发者工具里对 `cloudfunctions/` 下的每个云函数右键「上传并部署：云端安装依赖」。
4. 给 `autoExpire` 和 `keepWarm` 上传触发器（配置在各自的 `config.json` 里）。
5. 在云数据库里给自己的 `users` 记录加上 `super_admin` 角色，即可看到管理入口。
6. 云数据库手动建集合 `group_items`，权限选「所有用户可读，仅创建者可读写」（和 `task_items` 一样）。

`project.private.config.json` 是开发者工具的本地设置，不入库。

## 角色

用户角色存在 `users.roles` 数组里，新用户默认 `['student']`。管理权限在云函数内校验（见 `handleReport`、`deliveryManage`），不依赖前端判断：

- `super_admin` — 全部权限
- `market_admin` — 二手市场：删帖、处理举报
- `ops_admin` — 配送相关的运营权限（商家和配送队都不再审核，提交即生效）
- `sublet_admin` / `task_admin` / `group_admin` — 对应板块的删帖权限

管理入口在「我的」页面按角色显示：举报处理 `pages/reports`。（`pages/settlement` 还注册着，但已经没有任何入口——那套店长↔配送队对账流程目前不接入。）

**商家没有事前审核，门槛是开店码**：凭码开店，开团前要先上架商品。内容治理走事后路线——机检（`contentCheck`）+ 用户举报（`submitReport`）+ 人工复核下架（`handleReport`）。店铺被判违规时不删记录，而是打 `takedown` 标记（`status` 同时写 `closed`）：列表不再显示、开不了团、下不了单，还在拼团中的场次和单一起取消。

**配送队也没有事前核对**（2026-09-20 撤掉，`pages/shopaudit` 和 `deliveryManage` 的 `listForAudit` / `audit` 一并删除）：建队即可用。原来留着核对是因为队伍会碰到别人的订单和买家联系方式；现在平台既不派单也不下发买家信息，一条配送请求里只有店长自己的微信。

队伍也没有「营业中 / 打烊」开关，也没有可配送时段（2026-10-10 撤掉，`delivery_teams.availability` 老数据留着不读）：队伍建好就一直可选，哪一趟能不能送，店长发请求后两人在微信里定。队长在配送工作台可以「接下这单」或「不接」，不接时店长会收到通知、可以换一支队。

2026-10-10 起配送队有了门槛和事后治理：
- **开队码**：建队要填管理员在「我的 → 配送管理」生成的 8 位码，一码一队、7 天过期（集合 `team_create_codes`，控制台建、权限设为仅云函数可读写）。之前建好的队不受影响。
- **配送费即报酬**：小店设置里的配送费（送上门一口价 / 每个取货点各自的价）就是付给配送队的价。店长在「找配送队」页只填单数，合计由云函数按店铺现算并存快照；配送费为 $0 的不让发。小店设置里的「谁来送 / 绑定配送队」已删除，每一趟找不找队在「找配送队」页定。
- **送上门只送名单里的楼**：买家选「送到买家地址」时，从楼栋名单里挑楼（明大 Minneapolis 校区 East / West Bank + 周边约 1 mile 的公寓，不含 St Paul），再填房间号。名单里没有的可以在下单页选「其他」手填：订单上标「名单外地址」让店长确认，同时自动写一条「楼栋补录」意见反馈给管理员。名单在集合 `delivery_buildings`，由 `buildings` 云函数读写，管理员在「我的 → 配送楼栋」里导入初始名单、增加、改名、启用 / 停用。线下交付的单要填手机号，只给这一单的店长看。
- **群发 · 先接先得**：店长可以把请求发给所有队，第一个接下的拿到；接单前看不到店长微信。
- **举报 / 下架**：配送队可被举报（`submitReport` 的 `team` 类型），管理员在举报处理里下架，或在配送管理里手动下架 / 恢复。下架只打 `takedown` 标记，不删记录。
- **防爽约**：队伍接了去不了可以「退单」（不记爽约）；店长可以把接了没来的单标成「没来送」，记在 `no_show_count` 上，满 3 次自动下架。送达 / 爽约次数显示在店长挑队的卡片上。

红线改用**负面清单前置**而不是按品类分发条款：`components/banBar` 常驻在店铺设置和商品编辑页顶部，所有商家看同一份禁售清单，完整版在《商家责任告知书》第五节。《商家责任告知书》里食品相关的义务改成条件式表述（「如果你销售食品，你还必须…」），不做按分类的条件渲染。商家可在店铺设置里写一段 `order_notice`（下单须知），展示在店铺页——平台不生成也不审这段。

## 目录

```
miniprogram/       小程序前端
  config.js        功能开关
  pages/           页面
  utils/           公共方法
cloudfunctions/    云函数，权限校验都在这里
```

`autoExpire` 是定时触发器（每天 02:00），`keepWarm` 每 5 分钟调一次常用云函数防止冷启动，其余云函数由前端 `wx.cloud.callFunction` 调用。
